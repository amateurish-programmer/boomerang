# Android OTA implementation and acceptance

Goal: deliver user-triggered, verified APK updates from the project's existing Singapore Supabase service, and demonstrate a data-preserving upgrade on the connected phone.

Architecture: this adds a new application update capability. Use public-read Supabase Storage for immutable APKs and a small latest manifest. Keep publication credentials in Secrets. Android uses UI → ViewModel → update repository; no changes to record databases or backend business contracts.

Alternatives considered: private GitHub downloads would require distributing credentials; an additional update server adds operations without benefit. Existing Supabase Storage is the selected delivery service. Full APK installation uses Android's confirmation flow; no silent or differential installation.

Tech stack: Kotlin, Compose, coroutines, Android PackageManager/FileProvider; Node built-ins for publishing; existing signed GitHub workflow.

## Binding specification

- Manifest URL: `https://skeghmapzrmahxehazlp.supabase.co/storage/v1/object/public/app-updates/android/latest.json`.
- JSON camelCase fields: `schemaVersion` (1), `packageName` (`com.boomerang.app`), `versionCode` (integer 1–2100000000), `versionName` (1–80 characters), `minSdk` (integer >=26), `apkUrl`, `sha256` (64 lowercase hex), `sizeBytes` (positive integer <=67108864), `notes` (1–4000 characters), `publishedAt` (UTC ISO instant).
- APK URL must exactly equal `https://skeghmapzrmahxehazlp.supabase.co/storage/v1/object/public/app-updates/android/<versionCode>/app.apk`, with no credentials, query, fragment or foreign redirect. Manifest response <=64 KiB; network timeouts and bounded streaming required.
- Only newer compatible versions can install. Verify downloaded byte count and SHA256, actual APK package/version/minSdk, and pinned release signer `748d6f30358c0be6b96e1ae29cd2538659f7b8f09ac1a40649f20bf26f08afd2`; also require installed signer compatibility. Support API26 signature APIs.
- Download explicitly from the update screen; show progress, errors, retry/cancel. Keep verified download metadata in app-private storage; restore and revalidate before installation. Interrupted partial downloads may restart from zero with a clear retry state. Never present partial content as installable.
- UI entry: 我的 → 版本与更新, independent of login; show current version, check, notes/size, download, install. Unknown-source permission is for this package only, refreshed on return; installation still requires explicit user action. Grant installer read access only to a dedicated cache file using existing FileProvider.
- Publisher verifies actual APK metadata and pinned certificate. Create/configure `app-updates` public-read bucket without client write policies. Upload version path without overwrite, verify public bytes, promote manifest last. Reject downgrade and conflicting same-version release; identical retries may succeed. Use no privileged keys in APK, logs or artifacts. Latest manifest cache=0; APK path immutable.
- Release workflow publish option defaults false. Real cloud and phone results must be distinguished from local fixtures and builds.

## Global constraints and execution rulings

User explicitly requested OTA development with an attached debug-enabled phone. Project AGENTS authorizes staged commits, cloud builds and deployment. These cover routine implementation, own-project Storage publishing and same-certificate phone cover installation; no repeated approval gate is necessary. Uninstalling the existing app, clearing its data, changing global phone security, or touching other projects is outside scope. Existing `puppet-dance.html` is unrelated and preserved. 百炼 remains deferred and production Cron stays off.

Root owns versions, integration, cloud credentials, device operations and reports. Client task owns Android update source/tests and shell/manifest integration. Publisher task owns publisher scripts, schema, workflow and operations guide. All Gradle runs are serialized by root. Tests use isolated fixtures; never run the destructive/reset-oriented emulator suite against the user's populated release app.
