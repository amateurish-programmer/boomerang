# P4 本地提醒与通知中心

## 范围

- WorkManager 每 6 小时扫描，进入应用与本地保存/删除后补扫；后台执行为尽力而为，不承诺准点。
- 截止前 7 天、1 天、当天分档；迟到扫描仅选当前最相关的一档，不连续补发历史三条。未知日期、非 ACTIVE、已有用户确认及软删除记录不提醒。
- 投递键含 owner / record / local revision / deadline / offset；独立 SQLite 通知库通过主键原子去重，重启保留。
- 提醒扫描读取最新记录，无旧的逐记录闹钟。延期到提醒范围外、确认、取消或删除会在补扫时清理已展示的系统提醒；修订内同档不会再次投递。
- 账号切换持久化当前命名空间，取消原账号 WorkManager 任务和系统通知；迟到 worker 在写通知前再次核对账号。
- 通知中心通过 ViewModel / Repository 读取当前账号最近 200 条提醒。Android 13+ 提供通知权限申请入口，拒绝时仍可查看本机通知；系统通知点击带账号及记录 ID，由主 ViewModel 校验账号后打开详情。
- 系统通知不显示原话；应用内通知显示原话节选、当前提醒和记录版本。

## 已取得验证证据

- 新增非法日期 / 时区行为测试，旧实现实际失败：`DateTimeParseException`，6 项中 1 项失败；修复后使用本机缓存的 Kotlin 2.1.20 编译器及 JUnit 4.13.2 独立运行，`OK (7 tests)`。
- 7 项策略测试覆盖：最近档位、记录时区、未知/取消/远期、过期单档、账号/期限隔离、重复扫描稳定键及修订变更、非法日期与时区。
- 新增 Android instrumentation：SQLite 重复投递、关闭重开仍去重、账号隔离、修订变更可新增；Compose 通知中心展示持久化消息并点击返回准确记录 ID。

## 尚未验收

- 本阶段整体 Gradle / lint / APK、上述 instrumentation 的编译与实际执行由集成验证补充，不能把独立 JVM 通过称为 Android 验收完成。
- Android 13+ 权限拒绝/重新开启、从系统通知冷启动与热启动直达详情、设备重启、账号切换竞态和厂商后台时效需模拟器及真机验收。
- 本机通知库独立于 Room 记录库；云端通知同步与 P7 复核通知尚未纳入本机通知中心，不宣称云端通知中心已完成。
- 去重账本先持久化后发送系统通知；进程若恰在两者间退出，应用内条目仍在，但不会补发系统提示，以避免重复投递。
- 尚无本阶段独立提交 / CI URL；由主任务完成集成验证后记录。
